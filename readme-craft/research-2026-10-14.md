# README patterns that grab attention and convert visitors

Date: 2026-10-14. Scope: 18 popular open-source GitHub READMEs (15 mainstream, 3 VTuber/avatar), plus the topic page github.com/topics/vtuber. Method: each README fetched and summarised against one fixed question list. Star counts are as shown on the page at fetch time and will have moved.

Caveat: the fetch tool returns a flattened text view of the rendered Markdown. It cannot show raw HTML attributes reliably, so "no `<picture>` tag" means "no dark/light switching visible in the extracted text", not a verified absence. Confirm any specific trick by opening the raw file (`https://raw.githubusercontent.com/<org>/<repo>/HEAD/README.md`) before copying it.

## 1. The repos and what each README does

**Creative and whiteboard tools**

- **Excalidraw** (134k stars), https://github.com/excalidraw/excalidraw. Linked banner, then the tagline "An open source virtual hand-drawn style whiteboard." Six badges (license, npm downloads, PRs welcome, Discord, DeepWiki, Twitter). A large product screenshot follows, linked to the site. Install is about two screens down, after the feature list. Social proof is a "who's integrating" company list, sponsor avatar grids and thanks to Vercel, Sentry and Crowdin. Tricks: badges built from URL parameters; sponsor avatars linked by tier.
- **tldraw** (50.9k), https://github.com/tldraw/tldraw. Full-width hero image (`github-hero-light.png`, no picture tag). Pitch is a heading: "Build infinite canvas apps in React with the tldraw SDK," with Docs, Examples and Starter kits links under it. Install comes late. Social proof is a plain comma list of brands ending "and many more." Tone is promotional; the About text carries an unsupported superlative.
- **Penpot** (61k), https://github.com/penpot/penpot. Opens with a video, "OpenYourEyes", not a logo. Pitch: "the open-source design platform for teams that build digital products at scale." Digital Public Goods badge and community counter. Installation is mid-page. Features are short H3 blocks with bold keywords, plus a couple of screenshots. Long and promotional.

**Developer tools and runtimes**

- **Bun** (96.2k), https://github.com/oven-sh/bun. Single centred logo, three badges (Discord, stars, a "speed" badge). "What is Bun?" in two paragraphs, then install within about 150 words. Features are shown as shell code blocks with inline comments, not a feature grid. No hero media. Terse and confident.
- **Ghostty** (62.2k), https://github.com/ghostty-org/ghostty. Logo, no badges, one-line pitch "Fast, native, feature-rich terminal emulator pushing modern features." Hero is only the logo. The Download section links to the website and has no commands. Roadmap as a table with ✅/❌ marks. Social proof is in prose ("stable and in use by millions of people and machines daily").
- **Tauri** (111.9k), https://github.com/tauri-apps/tauri. Splash image, eight badges (status, licence, tests, FOSSA, Discord, website, Open Collective, a "greater good" badge). Getting started is early: one `npm create tauri-app@latest` command. Features are a plain bullet list. No screenshots. Terse and technical.
- **ratatui** (23k), https://github.com/ratatui/ratatui. Full-width banner, eight badges, pitch "a Rust crate for cooking up terminal user interfaces (TUIs)" with a pronunciation guide. Quickstart comes almost immediately: a `cargo-generate` command and a Hello World sample. No feature list; the code is the demo. Offers a copyable "Built With Ratatui" badge, a showcase link and an awesome list.
- **Zed** (91.7k), https://github.com/zed-industries/zed. Plain "Zed" heading, no logo, two badges. Pitch: "a high-performance, multiplayer code editor from the creators of Atom and Tree-sitter." No hero media. Install is within the first few lines. Social proof is lineage (Atom, Tree-sitter). Very short.
- **Bevy** (49k), https://github.com/bevyengine/bevy. Centred logo, five badges (licence, crates.io, downloads, docs, Discord). Pitch: "A refreshingly simple data-driven game engine built in Rust." No screenshot or GIF. Features are six bold-labelled bullets under "Design Goals." A WARNING section admits the API changes often and the docs are sparse. Candid, which builds trust.
- **Godot** (118.5k), https://github.com/godotengine/godot. Logo and one editor screenshot of a 3D scene about a fifth of the way down. Features are prose, not a list. Install links out. Social proof is the Foundation and open-sourcing history. Neutral, factual, long on context.

## 2. The 10 patterns that recur in the best READMEs

1. **A one-line pitch in the first screen, in plain words.** Examples: Ghostty ("Fast, native, feature-rich terminal emulator"), Bevy ("A refreshingly simple data-driven game engine built in Rust"), Ratatui ("a Rust crate for cooking up terminal user interfaces"), Immich ("High performance self-hosted photo and video management solution"). A reader should be able to say what it is in five seconds.
2. **One hero object, not a wall.** Excalidraw, Immich, Godot and Open WebUI show one product screenshot under the logo. Penpot and Amica use a video or a release-video thumbnail. The hero shows the product in use, not a logo cloud.
3. **Install or try within the first screen of text.** Zed, Tauri, Ratatui, airi and Bun put a command or download early. Ratatui's Hello World and Tauri's `create` command are the model. Projects that bury install (Immich, Penpot, Amica, OpenSeeFace) convert the curious less well.
4. **Badges used sparingly, with a purpose.** Tauri and Bevy keep to a small set (licence, CI, registry, Discord). Open WebUI's nine shields and Excalidraw's six are denser. Badges carry trust signals; they are not decoration.
5. **Features shown as a scannable structure, matched to the product.** Immich's Yes/No/N/A table fits a product with many platform comparisons. Bevy's six bold "design goals" suit a framework. Bun shows features as runnable commands. Excalidraw and tldraw use bullet lists with bold lead-ins. Pick the form the product's claim needs.
6. **Honest scope signals.** Bevy's WARNING that the API changes often, and Ghostty's roadmap with ✅/❌ marks. Saying what is not ready builds trust in what is.
7. **Proof that is specific.** Tauri's sponsor logo, Immich's Repobeats and contributor graph, airi's Trendshift and Product Hunt badges, Excalidraw's company list. Generic praise does nothing; named users and live numbers do.
8. **Light and dark handled deliberately.** Supabase's `#gh-light-mode-only` / `#gh-dark-mode-only` fragments, airi's light-theme banner, Bevy's logo variants. Most projects skip this and ship one image; a transparent or two-variant logo is the cheap version.
9. **Sections that carry depth without blocking the top.** Ollama and Godot push long integration lists or details down. Tables and `<details>` (not seen in these fetches, but the usual tool) keep the first screen short while the depth stays available.
10. **A clear next step for each audience.** Users (download), developers (quickstart and docs), contributors (CONTRIBUTING, "good first issue"), sponsors (a call to action). Open WebUI and Bevy both end sections with a thanks or sponsor line. Each reader should know where to go next.

## 3. Anti-patterns that make a README feel generic or AI-written

- **Superlatives with no evidence.** tldraw's "World's best, top-most agent recommended #1 five star SDK." Say what it does and let the reader judge.
- **Emoji in every heading or bullet.** Open WebUI, Amica and ratatui use them sparingly. Overuse reads as template.
- **A feature grid of identical icons and one-word labels.** It reads as a landing page template with no product in it.
- **Empty anchor links before every heading** (`[](#anchor)`). Found in tldraw, Ollama, Zed, Bun, Ghostty and Penpot. Harmless, but it shows the README was generated or templated.
- **A logo cloud with no context.** tldraw's "and many more" brand list; Excalidraw's company list. Credibility only if the brands are current and linked.
- **Install buried below a long feature story** (Immich, Penpot, Amica). The reader is already gone.
- **Vague claims with no number.** "Stable and in use by millions of people" with no source (Ghostty). Give a number, a date or a link.
- **Repeating the About block** at the bottom of the README (OpenSeeFace, Amica). Redundant copy in the README is a sign nobody edited it.
- **Mermaid or diagrams with no explanation** of what the reader should take away. Use them only where the architecture is the selling point (airi does this well).
- **A "why" section that is only adjectives.** "Fast, elegant, powerful." Show the benchmark, the demo or the screenshot instead.
